Run Cedarside on your computer

A start-to-finish guide to installing the furniture manufacturing & delivery monitoring system locally — the Laravel API and the React storefront/CRM. No prior Laravel or React experience assumed. Follow every step in order and tick it off.

Time
~20–30 min
You'll run
2 terminals
Backend
Laravel 12 · PHP 8.2
Frontend
React 18 · Vite
The mental model. This app is two programs that talk to each other. The backend (Laravel) is the API + database, running at http://127.0.0.1:8000. The frontend (React) is the website you look at, running at http://localhost:5173. You keep both running at the same time in two separate terminal windows. The frontend automatically forwards its /api calls to the backend, so there's nothing to wire up by hand.
Pick your OS once. Use the Windows / macOS·Linux switch in the top bar — every command below updates to match. It's set to Windows to start.

Install the prerequisites

You need these five tools first. If you already have them, skip ahead — but check the versions.

Git any

Downloads the code. Get Git ↗

PHP 8.2 or newer

Runs the backend. On Windows the easiest way is Laravel Herd ↗ (bundles PHP + Composer).

Composer 2.x

Installs PHP packages. Get Composer ↗ (included in Herd).

Node.js 20 LTS+

Runs the frontend (includes npm). Get Node ↗

A code editor optional

For editing the .env file — VS Code ↗ or Notepad works.

Then verify each one is installed. Open a terminal (Windows: PowerShell; macOS: Terminal) and run these one by one — each should print a version number, not an error:

verify tools
git --version
php --version
composer --version
node --version
npm --version
Node must be 20 or higher. If node --version shows v18 or lower, the frontend build will fail — install the current LTS from the link above and reopen your terminal.

Download the code

Pick a folder you'll remember (e.g. your Documents), then run:

clone

cd FurnitureManagementSystem

Inside you'll find two folders: backend (Laravel) and frontend (React). That's what the next two tracks set up.

2

Set up the backend

Terminal 1

Everything in this track happens inside the backend folder. Keep this terminal open — it'll run the API server at the end.

2.1
install dependencies
cd backend
composer install

This downloads Laravel and all its packages into vendor/. It can take a couple of minutes the first time.

2.2

Copy the example file to a real one:

PowerShell
Copy-Item .env.example .env
bash / zsh
cp .env.example .env
2.3
app key
php artisan key:generate

This fills in APP_KEY in your .env. Some data (like saved addresses) is encrypted with it, so don't skip this.

2.4

SQLite is a database in a single file — nothing to install. Open backend/.env in your editor and change the database line to:

backend/.env
DB_CONNECTION=sqlite

Then delete (or comment out with #) these four lines just below it, so they don't confuse SQLite:

backend/.env — remove these
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=furniture_monitoring
DB_USERNAME=postgres

Now create the empty database file:

PowerShell
New-Item -ItemType File database/database.sqlite
bash / zsh
touch database/database.sqlite
Prefer PostgreSQL instead? (optional)

The project's example is configured for Postgres. If you have PostgreSQL 17 ↗ installed, keep DB_CONNECTION=pgsql and instead create a database named furniture_monitoring, then set DB_USERNAME / DB_PASSWORD in .env to your Postgres login. Skip the SQLite file step above. Everything else in this guide is identical.

2.5

Find ADMIN_PASSWORD in backend/.env and give it a value — this becomes your super-admin login. For local use anything memorable is fine:

backend/.env
ADMIN_PASSWORD=password123
Don't leave this blank. If ADMIN_PASSWORD is empty, the seeder skips creating the admin account and you won't be able to log in to the CRM.
The keys you can ignore locally. Leave MESHY_API_KEY and BREVO_API_KEY empty. The app runs fine without them: 3D generation is simply disabled (you can still upload a .glb by hand), and emails are written to storage/logs/laravel.log instead of being sent.
2.6
migrate & seed
php artisan migrate --seed

This builds every table and runs the RolePermissionSeeder, which creates all the roles/permissions and your super-admin account (admin@cedarside.local). Type yes if it asks to create the SQLite database.

2.7
storage link
php artisan storage:link

Lets uploaded images and 3D files be served during local dev.

2.8
run backend
php artisan serve

Leave this running. You should see Server running on http://127.0.0.1:8000. Test it by opening http://127.0.0.1:8000/api/v1/health — it should return a small JSON with "status":"healthy".

That's the backend done. Open a new terminal window for the frontend — don't close this one.

Set up the frontend

Terminal 2

In your second terminal, go back to the project root and into frontend.

3.1
install dependencies
cd frontend
npm install

Downloads React, Vite and everything else into node_modules/.

3.2

For local dev the frontend needs no configuration. The Vite dev server automatically forwards /api requests to the backend on port 8000. (The VITE_API_URL setting is only used in production.)

3.3
run frontend
npm run dev

Leave this running too. It prints a local URL — usually http://localhost:5173.

You shipped it! 🎉 Both servers are running and you're logged in. Everything below is reference material.
5

Optional: enable 3D generation

Product photos turn into 3D models via the Meshy AI service. This is optional — skip it unless you want to test that feature.

  1. Get an API key from Meshy and put it in backend/.env as MESHY_API_KEY=....
  2. Generation runs on a queue, so start a worker in a third terminal (inside backend):
queue worker (backend)
php artisan queue:work
No key? No problem — leave it empty and upload a .glb file manually when creating a product. The 3D viewer still works.

Troubleshooting

The usual first-run snags and their fixes.

composer install fails: "could not find driver"

A PHP database extension is off. Open your php.ini and remove the ; in front of extension=pdo_sqlite (and extension=pdo_pgsql if using Postgres), plus extension=mbstring, fileinfo, openssl, curl. Save and reopen your terminal. If you used Laravel Herd, these are already enabled.

The website loads but data won't load / network errors

Make sure the backend is still running in Terminal 1 (php artisan serve) and that you opened http://localhost:5173 — not port 8000. The frontend proxies to the backend, so both must be up.

Port 8000 (or 5173) is already in use

Run the backend on another port with php artisan serve --port=8001, then in frontend/vite.config.ts change the proxy target to http://127.0.0.1:8001 and restart npm run dev. Vite will also auto-pick a new port (5174…) if 5173 is taken.

Login says invalid credentials

You almost certainly seeded before setting ADMIN_PASSWORD. Set it in .env (step 2.5), then re-run php artisan migrate:fresh --seed to recreate the admin. Use admin@cedarside.local as the email.

3D viewer just says "Loading model…"

Expected locally without a MESHY_API_KEY — no model was generated. Either set the key and run php artisan queue:work (step 5), or upload a .glb file manually on the product page.

No emails arrive (welcome / order updates)

Also expected locally. With MAIL_MAILER=log, emails are written to backend/storage/logs/laravel.log instead of being sent. To send real email, set a Brevo API key in BREVO_API_KEY.

npm install or npm run dev errors

Check node --version is 20+. If it's older, install the current LTS and reopen your terminal. If problems persist, delete frontend/node_modules and run npm install again.
